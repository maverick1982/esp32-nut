# ADR Governance

This project uses Architectural Decision Records (ADRs) to govern architectural choices.

When working on this repository, you MUST:
1. Consult docs/adr/README.md before generating any Implementation Plan or performing architectural/refactoring tasks.
2. Strictly respect all ADRs with the Accepted status as non-negotiable constraints.
3. NEVER introduce new dependencies, design patterns, or architectural changes that violate an existing Accepted ADR without explicit prior discussion with the user.
4. Explicitly indicate in your Implementation Plans whether the proposed work touches, respects, or introduces a new ADR.
