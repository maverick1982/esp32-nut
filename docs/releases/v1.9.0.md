UPS support release: dedicated drivers for Legrand Keor and Powerwalker (Phoenixtec) UPS units, CyberPower variables aligned with NUT, and fixes for the APC Back-UPS Pro BGM2200 and for UPS units that are slow to answer when they are plugged in.

## ⚠️ Upgrade notes

- **The driver name moved from `ups.type` to `driver.name`.** In NUT `ups.type` is the UPS topology (for example "offline / line interactive"), not the driver: esp32-nut now publishes the driver in `driver.name`, as `usbhid-ups` does. On Eaton UPS units `ups.type` now always shows the topology. If a Home Assistant sensor or a script read the driver name from `ups.type`, switch it to `driver.name`.
- **AC present and discharging at the same time is now `OL DISCHRG`, not `OB DISCHRG`.** Some UPS units (for example the APC Back-UPS Pro BGM2200) report both while they are on mains. esp32-nut now shows them as on line, as NUT does with its default settings, so Home Assistant, upsmon and WinNUT no longer see the UPS on battery when it is not. When mains is really lost the status is still `OB`. ([#98](https://github.com/maverick1982/esp32-nut/issues/98))
- **CyberPower values that were wrong change on update:** on PID `0501` models, `battery.voltage` is scaled like NUT's `cps-hid` (for example 13.9 V instead of 20.8 V on a 12 V battery) and `input.frequency` / `output.frequency` no longer read ten times too high (50.1 Hz instead of 501.0 Hz). ([#43](https://github.com/maverick1982/esp32-nut/issues/43))

## New and improved UPS support

- **Legrand Keor PDU and Keor SP** (`1CB0:0038`, `1CB0:0032`): dedicated driver after NUT's `legrand-hid`. The beeper commands use the Legrand values (`beeper.mute` is not offered, as in NUT), and the overload flag, warning capacity limit, battery voltage and outlet load are now read. Tested on a Keor PDU 800. ([#90](https://github.com/maverick1982/esp32-nut/issues/90))
- **Powerwalker and other Phoenixtec UPS units** (`06DA:FFFF`): dedicated driver after NUT's `liebert-hid`. The nominal output voltage and frequency are no longer shown as input values, `battery.type` is read, and the commands are those of NUT (battery test, load on/off, delayed shutdown, beeper). Tested on a Powerwalker VI 2200 SHL, including the beeper, load and battery test commands during a power outage. The Salicru SPS SOHO+ uses the same USB ID. ([#96](https://github.com/maverick1982/esp32-nut/issues/96))
- **CyberPower:** besides the scale fixes above, new variables as in NUT's `cps-hid`: `ups.firmware`, `battery.type`, `battery.charge.warning`, `battery.status`, `battery.mfr.date`, `ups.power.nominal` and the `ups.timer.*` timers. `ups.realpower` is estimated from the load only when the UPS does not measure it. ([#43](https://github.com/maverick1982/esp32-nut/issues/43))
- **APC Back-UPS Pro BGM2200:** load, nominal battery and input voltage, real power and runtime were shown as 0. They are now read correctly: the USB description of this model declares each value 23 times, and esp32-nut now reads the first one, as NUT does. ([#98](https://github.com/maverick1982/esp32-nut/issues/98))

Confirmed by users on real hardware: **APC** Back-UPS Pro BN1050M ([#83](https://github.com/maverick1982/esp32-nut/issues/83)) and BGM2200 ([#98](https://github.com/maverick1982/esp32-nut/issues/98)), **CyberPower** UT850EG (Discussion #95), **Legrand** Keor PDU 800 ([#90](https://github.com/maverick1982/esp32-nut/issues/90)), **Powerwalker** VI 2200 SHL ([#96](https://github.com/maverick1982/esp32-nut/issues/96)).

## Fixes

- **UPS not detected until it was unplugged and plugged in again:** a UPS that did not answer the first USB description request when it connected (for example right after resetting its own USB port) was ignored for good. The request is now retried up to 5 times, 2 s apart. ([#97](https://github.com/maverick1982/esp32-nut/issues/97))
- **NUT server, closer to `upsd`:** `GET VAR` repeats the variable name as the client wrote it (upper or lower case), and the internal `ups.status.*` helper keys are no longer reachable with `GET VAR`, `LIST ENUM`, `LIST RANGE` or `SET VAR` (they answer `ERR VAR-NOT-SUPPORTED`, as they were already hidden from `LIST VAR`).
- **System Log:** when a UPS reports AC present while discharging with the battery below 100 %, a warning is logged, at most once per change of the charge, as NUT does.

## Other changes

- **License:** from this release esp32-nut is distributed under **GPL-3.0-or-later**, because parts of it are derived from the NUT sources (GPL). Releases up to v1.8.0 stay under MIT. The `NOTICE` file lists the earlier MIT contributions and the third-party components.
- **Tests:** replay fixtures from the Legrand Keor PDU 800, Powerwalker VI 2200 SHL, CyberPower UT850EG and APC BGM2200 dumps (on mains and on battery) run on every change.
