Feature release: esp32-nut can now **control** your UPS, not just monitor it. You can run UPS commands (battery test, beeper, load and shutdown) and change the UPS parameters, from the Web UI or with the standard NUT tools (`upscmd`, `upsrw`, Home Assistant). The Web UI is now protected by a login, the NUT server accepts up to 8 clients, and OTA updates no longer fail on slow Wi-Fi.

## ⚠️ Upgrade notes

- **Create the Web UI credentials right after the update.** Every page of the Web UI, OTA included, now requires a login. On the first visit after the update the Web UI shows only a **Create credentials** form, and whoever fills it in first becomes the administrator. These credentials are separate from the NUT ones, which Home Assistant, PeaNUT and other NUT clients keep using as before. The "Web UI Login" section of the [README](https://github.com/maverick1982/esp32-nut#readme) explains the rules, "Remember me" and how to reset a forgotten password.
- **The UPS name is never empty.** NUT clients address the UPS by the **UPS Name** of the NUT tab. If it was never set, it is now `ups` (e.g. `upsc ups@<board-ip>`). Before, an empty name made Home Assistant fail with `LIST VAR: ERR INVALID-ARGUMENT`.
- **NUT commands without the UPS name are rejected**, as with `upsd`: `LIST VAR`, `GET VAR battery.charge` and similar now answer `ERR INVALID-ARGUMENT` instead of falling back to the configured UPS. Standard clients always send the name, so this only matters for hand-written scripts.
- **`LOGIN`, `SET` and `INSTCMD` need `USERNAME` and `PASSWORD` first** when NUT credentials are set in the NUT tab, as with `upsd` (`ERR USERNAME-REQUIRED` / `ERR PASSWORD-REQUIRED`). Without NUT credentials nothing changes.
- **Quotes, backslashes and `#` in NUT values are escaped** in `VAR`, `RW` and `ENUM` replies, as `upsd` does. NUT clients decode them; only scripts that parse the raw protocol can notice.
- **Web UI changes:** the beeper switch is gone from the UPS Telemetry page. The beeper is now controlled from the **UPS Commands** page (`beeper.enable`, `beeper.disable`, `beeper.mute`) or with `upscmd`. The undocumented `POST /api/beeper` endpoint and the `ups.beeper.switchable` field of `/api/ups-vars` were removed.
- **Coming from v1.5.x or earlier:** install with the [web installer](https://maverick1982.github.io/esp32-nut/), not with an OTA update (see the [v1.6.0 notes](https://github.com/maverick1982/esp32-nut/releases/tag/v1.6.0)).

## New features

- **UPS commands** over NUT and in the new **UPS Commands** page. Each UPS offers the commands its USB interface supports, as with NUT's `usbhid-ups` driver ([#23](https://github.com/maverick1982/esp32-nut/issues/23), [#78](https://github.com/maverick1982/esp32-nut/issues/78)):
  - battery and panel tests (`test.battery.start.quick/deep`, `test.battery.stop`, `test.panel.start/stop`), with the last test result. PeaNUT's "Testing" menu now works;
  - beeper (`beeper.enable`, `beeper.disable`, `beeper.mute`);
  - load and shutdown (`load.off`, `load.on`, `load.off.delay`, `shutdown.return`, `shutdown.stayoff`, `shutdown.reboot`, `shutdown.stop`, `shutdown.default`), with the NUT delays `ups.delay.shutdown` / `ups.delay.start` (20/30 s, CyberPower 60/120 s). The Web UI asks for a confirmation before any command that can cut the power. No shutdown commands on Powercom, EcoFlow and OpenUPS.
  - Home Assistant offers them as device actions when the NUT integration has the NUT username and password.
  - `upscmd -w` waits for the outcome (`SET TRACKING`).
- **UPS settings** over NUT (`upsrw`, `LIST RW`) and in the new **UPS Settings** page: the parameters your UPS lets you change, such as low battery thresholds, transfer points, input sensitivity, battery date and shutdown delays. Values are read back from the UPS after each change. Driver values kept on the ESP32 (`ups.delay.*`, outlet names) survive reboots and have a **Reset to default** button. On APC, `battery.mfr.date` resets the battery date after a battery replacement ([#73](https://github.com/maverick1982/esp32-nut/issues/73)).
- **Web UI login:** username and password (stored as a salted hash), "Remember me" for 30 days, **Log out** and **Log out of all devices**, a growing wait after repeated wrong passwords, and a **Web Login** tab to change the credentials. In Access Point mode (double reset within 3 s) the Web UI stays open without login, to reset forgotten credentials, and the board goes back to the home network 10 minutes after the last device leaves the access point.
- **Up to 8 NUT clients at the same time** (was 4). When all slots are taken, the System Log shows which addresses hold them. A client that disappears without closing its connection frees its slot after about 90 s instead of 5 minutes. ([#84](https://github.com/maverick1982/esp32-nut/issues/84))

## Fixes

- **OTA update rebooting halfway on slow Wi-Fi:** an upload that took more than 30 s tripped the board's watchdog (`Reset reason: TASK_WDT`), and the board came back on the old firmware. Uploads now complete however long they take. ([#73](https://github.com/maverick1982/esp32-nut/issues/73))
- **APC Smart-UPS 750:** `beeper.mute` was missing and the beeper commands could fail, because this model declares the beeper twice. ([#78](https://github.com/maverick1982/esp32-nut/issues/78))
- **USB diagnostics:** the export keeps the full product string again (on APC the `FW:` part was lost since v1.7.2).
- **Web UI:** the sidebar keeps the same width on every page; UPS Commands, UPS Settings and UPS Telemetry no longer squeeze or clip their content on mid-size screens.

Confirmed by users on real hardware:

- **APC** Back-UPS XS 1500M, Back-UPS ES 600M1 ([#73](https://github.com/maverick1982/esp32-nut/issues/73)), Smart-UPS 750L and 1000L ([#23](https://github.com/maverick1982/esp32-nut/issues/23))
- **CyberPower** CP1500PFCLCDa (Discussion #72), CP1500PFCRM2U ([#84](https://github.com/maverick1982/esp32-nut/issues/84)), CP1600EPFCLCD ([#48](https://github.com/maverick1982/esp32-nut/issues/48)), SL700U (Discussion #79)

## Install

Flash it from the [web installer](https://maverick1982.github.io/esp32-nut/) or upload `firmware.bin` from the attached zip through OTA in the web UI. Then open the Web UI and create the web credentials right away (see the upgrade notes).
