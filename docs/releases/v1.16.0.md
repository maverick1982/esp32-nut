The board can now read UPS units that NUT drives with `nutdrv_qx` (the Megatec/Q1 family), starting with the ones on USB ID `0001:0000`. A Back-UPS BX that stops sending its status after a USB port power cycle no longer stays frozen for hours.

## New features

- **Q\* UPS units (Megatec/Q1, `nutdrv_qx`)** (#91, #28). Some UPS units show up on USB as HID devices but send their data with a protocol of the Megatec/Q1 family. NUT drives them with `nutdrv_qx` instead of `usbhid-ups`, and until now the board showed them as not detected.
  - The board recognizes them by their USB ID, as NUT does, and runs the same protocols: `megatec`, `megatec/old`, `mustek`, `zinto`, `hunnox`, `innovatae` and `q1`. NUT clients see `driver.name: nutdrv_qx`, and `driver.version.data` names the protocol in use.
  - Supported for now: UPS units with USB ID `0001:0000` that NUT handles with the `krauler`, `fabula` or `hunnox` USB subdriver (for example Krauler, Fideltronik/MEC LUPUS, Hunnox, and other units whose USB product name is `MEC0003`).
  - **Board Settings → Q\* UPS driver**, shown only with a Q* UPS connected: the protocol the board detected, plus the `protocol` and `novendor` options of NUT's `ups.conf`. Leave Protocol on **Automatic** unless NUT needs a specific one for your model: some protocols answer the same probe (`hunnox` is detected as `megatec`), as in NUT. Changes apply at once, with no restart.
  - `langid_fix` is applied by itself when the UPS needs it: the board tries again with US English when the normal read fails, and keeps using it if the UPS answers.
  - Commands work from the **UPS Commands** page and with `upscmd`, as with `nutdrv_qx`. Which ones the UPS accepts depends on its USB chip: some units reject the battery test, in NUT too.
  - **Export USB Diagnostics** has a new `qx` section with the commands sent to the UPS and its answers.
  - Tested on a VIDA Armour 1200VA, with Protocol `hunnox` and novendor on. The `fabula` transport has not been tested on a real UPS yet.
  - Q\* UPS units with other USB adapters (Cypress, Phoenix, Ippon, …, such as the Voltronic Power units with USB ID `0665:5161`) are recognized but not supported yet. A yellow box in the web UI says so, and asks for an issue with the USB Diagnostics export.

## Fixes

- **Back-UPS BX frozen after a USB port power cycle** (#138). On a Back-UPS BX750MI, a USB port power cycle sometimes left the UPS sending no more status reports, while it kept answering the board's requests with the same values. Everything then stayed frozen (`OL` even with the UPS unplugged from the mains) until the USB cable was unplugged. v1.13.0 hid this because it restarted the board for every stuck USB request, and a restart frees the UPS. Since v1.14.0 the port power cycle replaced most of those restarts, so nothing cleared the freeze any more.
  - Now, on a Back-UPS BX, 15 seconds without status reports mark the data as stale, and the board restarts at once. The System Log shows `[USB] No INPUT report for 15 s since the UPS connected: UPS values likely frozen`.
  - On the reporter's BX750MI, 3 of 44 power cycles in 16.5 hours froze the UPS, and each one was over in about 20 seconds. Home Assistant (60 s poll) saw the UPS unavailable for 10-20 s at most.
  - The newer BXR series is not affected and is left out of this check.

## Known issues

- **The web installer cannot flash an ESP32-P4 v3.1 or later yet** (#136). ESP Web Tools 10.4.0 includes esptool-js 0.6, which does not power on the flash of these chips, and the installer stops with "Failed to initialize". Flash the release zip with esptool instead (see **Release packages** in the README). Boards already running ESP32-NUT update through OTA as usual.

## Other changes

- **README:** on the Waveshare ESP32-P4-ETH the UPS goes on the 4-pin header J3, with all four wires including 5V: the USB-C port is not a host port (#140). The README also has a new section on Q* UPS units, and the APC Back-UPS BXR1200MI now has its own line among the tested models, apart from the BX notes.
