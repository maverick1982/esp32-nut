Platform release: esp32-nut moves to ESP-IDF 5.5 and gets the groundwork for more boards (ESP32-P4 with Ethernet, #94). For ESP32-S3 users it adds a Board Settings page to turn the status LED off or dim it, and a lighter USB diagnostics export.

## ⚠️ Upgrade notes

- **New platform: ESP-IDF 5.5** (pioarduino 55.03.312-1, was ESP-IDF 5.1). The update through OTA works as usual and keeps Wi-Fi, NUT and web credentials and the UPS settings: it was tested from v1.8.0 on an ESP32-S3 with an Eaton 3S. NUT clients see the same variables, commands and writable settings as with v1.9.0. If your UPS behaves differently after the update, please open an issue and attach the USB diagnostics export.

## Other changes

- **Board Settings page** in the web UI (after login), panel "Hardware options":
  - **status LED on/off**: when off, the LED stays off in every state, also after a restart;
  - **LED brightness** on 5 levels, applied at once and kept after a restart. The default is level 3, the same brightness as before;
  - the board name is shown at the top of the panel ("ESP32-S3 DevKitC-1").
- **USB diagnostics export** (System Logs → Export USB Diagnostics) is streamed instead of being built in memory first: same file, but the board no longer needs a large block of free memory to produce it, which keeps more memory free while NUT clients and the web UI are busy.
- **Groundwork for more boards** (ESP32-P4, Ethernet, #94): pins and capabilities of each board now live in one board profile, and the network goes through one interface for Wi-Fi and Ethernet. On boards without Wi-Fi, a double reset opens a 10-minute window to replace the web credentials. Nothing changes on the ESP32-S3: the P4 images will come in a later release.
- **Web API:** `GET/POST /api/board` reads and changes the board settings; `/api/system-status` now reports `network.type` (`wifi` or `ethernet`).
