The board can now shut the UPS down by itself on low battery, for UPSes that power devices without a NUT client. The "Wi-Fi Config" page becomes "Network", with a section for every link of the board, Ethernet included, and you can choose the hostname of each board.

## ⚠️ Upgrade notes

- **Wi-Fi hostname (ESP32-S3).** Without a chosen name, the board now sends `esp32-nut-xxxxxx` to the DHCP server, the last 3 bytes of its MAC address, as the Ethernet boards already do. Before, it sent the Arduino default `esp32s3-XXXXXX`. Check DHCP reservations, router rules or bookmarks that use the old name, or set the name you prefer in the new **Hostname** section of the Network page. Ethernet boards keep their name.
- **"Wi-Fi Config" is now "Network".** Same settings and same first-setup behaviour, under a new name and with the link status on top.

## New features

- **Automatic shutdown on low battery** (#100). In **Board Settings → Automatic shutdown**, off by default. With the option on, when the UPS is on battery and reports low battery (`OB LB`), the board sends `shutdown.default` to the UPS once, even with no NUT client connected. It does not send it again until the UPS is back on line (`OL`). This is meant for UPSes that power a TV, an audio system or other devices without `upsmon`.
  - The threshold is the one of the UPS: `battery.charge.low` / `battery.runtime.low`, in **UPS Settings**. There is no separate threshold on the board.
  - The command shows in the System Log as `[CMD] Automatic shutdown: ...`, followed by its outcome.
  - If the UPS offers no shutdown command, or no UPS is connected, the switch is disabled and the page says why.
  - It is a setting of the board, not a UPS variable. It does not appear in `upsrw` and NUT clients cannot change it. `upsmon` and the other NUT clients work as before.
  - Whether the UPS turns its outlets back on when power returns depends on the model. `shutdown.default` tries `shutdown.return` first. Tested on an Eaton 3S that also powered the board and the Wi-Fi router: the outlets went off about 20 s after the command and came back on about 30 s after power returned (`ups.delay.start`), and the board reconnected on its own.
- **Network page.** One section per link of the board, Wi-Fi or Ethernet, with its state, IP address, gateway, MAC, DHCP and the SSID and signal or the cable speed. The ESP32-P4 Ethernet boards get a network page for the first time. When the board stops answering, the last values stay greyed out with "No answer for N s".
- **Hostname** (#116). In the new **Hostname** section of the Network page, on every board. It is the name the board sends to the DHCP server on Wi-Fi and Ethernet, so you can find each board in the router's DHCP table or reach it by name. It accepts 1 to 32 letters, digits and hyphens, with no hyphen at the start or end. It is kept across OTA updates, and the board restarts when you change it.

## Fixes

- **Web UI:** an SSID with repeated spaces (for example `Home  Network`) is shown as it is in the Network page, in the notices and in the status bar, no longer with a single space.

## Other changes

- **Diagnostics:** after a restart caused by the task watchdog, the System Log names the tasks that stopped responding, for example `[DIAG] Watchdog: tasks not responding: ups_poll (CPU 0/1)`. The names also appear in the web UI crash banner and in the **Export USB Diagnostics** file. This helps to find the cause of a freeze from the log alone (#111, #112).
- **Tested hardware:** CyberPower CP2000EIPFCRM2U, on a Waveshare ESP32-P4-WIFI6-POE-ETH board (ESP32-P4 before v3, Ethernet) (#108). Its values are the same as with NUT, except `battery.mfr.date`, which is not shown yet.
