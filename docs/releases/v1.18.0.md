This release adds the Arduino Nano ESP32 as a fourth board, shows your custom NUT variables on the telemetry page, can take the NTP server from your router, and closes some gaps in the USB recovery found on APC Smart-UPS units.

## New features

- **Arduino Nano ESP32** (PR #149). The Arduino Nano ESP32 is now a supported board, with its own zip (`esp32-nut-v1.18.0-arduino-nano-esp32.zip`), its own `-ota.bin` for the online update and its own button in the web installer. It has no status LED, and pins D10-D13 are free for a W5500 Ethernet module.
  - For the first install, put the Nano in download mode: connect **B1 to GND** while you reset it, then pick its serial port in the web installer. After that, updates go through OTA as on the other boards.
  - The USB-C port is the one the UPS plugs into, so the Nano needs a USB-C OTG adapter that also powers the board and the UPS port. Tested with a CyberPower CP1500PFCLCDa and a CP685AVRG. While the firmware runs, the USB-C port is not a serial port: use the System Log, syslog or the UART pins.
- **Custom NUT variables on the UPS Telemetry page** (#143). The page now shows what NUT clients see next to what the UPS reports. A row whose value you override on the **NUT Server** page keeps the UPS value and gets an amber **NUT clients** chip with the value clients receive; a variable the UPS does not report gets a cyan **Added** chip. Your note appears under the description, the panel header sums up the custom variables, and the cards show a mark. Each chip, mark and the summary opens the record on the **NUT Server** page.
- **NTP server from DHCP** (#135). **Board Settings → Time → Use the NTP server from DHCP**, off by default. With it on, the board syncs with the NTP server your router announces (DHCP option 42). The server you typed stays saved and is used when the router announces none (static IP, access point mode), or when the router's server does not answer within 60 seconds. The **Time** section shows the server in use and where it comes from, and the System Log names it. With the switch off nothing changes.
- **Real power from the rating on the label** (#128). Some UPS units report only the load in percent, not the power in watts, nor their nominal power: the APC Smart-UPS 1500 of #128 is one of them. Add the rating as a custom variable on the **NUT Server** page, `ups.realpower.nominal` in W or `ups.power.nominal` in VA, and the board publishes `ups.realpower` = load × nominal power (× 0.6 for VA), updated with every new load reading, with no restart. Remove the variable and the estimate goes away.
  - A custom nominal power wins over the one the UPS reports, as it does for NUT clients. UPS units that measure or compute their own power (Eaton, for example) are never touched.
  - The estimate is right only if the UPS gives the load as a percentage of its watts. The **Real Power** card and the `ups.realpower` row show an **Estimated** badge whenever the value comes from the board, with the source and the formula in its tooltip. This also applies to the estimate the board already made from the nominal power reported by the UPS.

## Fixes

- **APC Smart-UPS: UPS not coming back after a recovery** (#78, #120). Two boards lost their Smart-UPS 750 after days of normal running, and one ended in degraded mode. Three gaps in the recovery are now closed:
  - the check that power-cycles the USB port when the UPS does not show up after a restart could turn itself off in exactly that case; it now works as intended;
  - after a USB port power cycle, the port could stay off if it was not ready to be powered on again; the board now retries until it is;
  - from the second automatic restart in a row, the web UI banner, the System Log and the diagnostics export (`first_restart_cause`) show the cause of the **first** restart of the series, not only the last one.
- **APC Smart-UPS: fewer stuck USB transfers** (#78). Smart-UPS units with an interrupt endpoint now get the gentler polling the Back-UPS BX already have: the values the UPS does not send by itself are read every 10 seconds, and the values that never change only once. This cuts the USB requests by about two thirds and with them the stuck transfers that lead to port power cycles.
- **Degraded mode message.** It now asks only to unplug and replug the UPS USB cable. Restarting the board from the web UI does not leave degraded mode, so the old advice to restart it did not help.
- **Estimated power no longer truncated.** When the board computes `ups.realpower` from the load and a nominal power, it now uses the load with its decimals: 10.4 % of 980 W is 102 W, not 98 W. On some UPS units the value can read a few watts higher than before.
- **Open NUT Server** now highlights the record also when it was saved with different capitals (for example `Battery.Charge.Low` instead of `battery.charge.low`). The override already worked, but the link opened the page without pointing to the row.

## Other changes

- **Tested UPS units:** the Cleanline Evolution 1000 (Mustek protocol over the Cypress bridge, `0665:5161`) is now in the README list (#154, #152). The CyberPower SL700U dump shared in discussion #79 is now a regression test.

## Install

Use **Download and install** on the OTA page, flash it from the [web installer](https://maverick1982.github.io/esp32-nut/), or upload `firmware.bin`, the `-ota.bin` of your board or the whole zip through OTA in the web UI.
