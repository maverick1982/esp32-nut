Bug-fix release. APC Back-UPS BX models now recover on their own from their frequent USB lockups, in a few seconds and without unplugging anything. `ups.status` no longer shows tokens that could make NUT clients shut down while the UPS is on mains.

## ⚠️ Upgrade notes

- **No more `FSD` or `COMM_LOST` in `ups.status`** ([#65](https://github.com/maverick1982/esp32-nut/issues/65)). When the UPS reports *shutdown imminent*, `ups.status` now shows `LB`, as upstream `usbhid-ups` does. Before, it showed `FSD`, which makes `upsmon` shut down immediately, even on mains. *Communication lost* no longer adds a token, because `COMM_LOST` is not a standard NUT status. If you have automations that match `FSD` or `COMM_LOST`, update them.
- **For a few seconds after a boot, NUT now answers "data stale"** while the board reads the UPS for the first time, like NUT on Linux does while its driver starts. Before, clients got an empty status, which Home Assistant showed as `unknown`. Now they see the UPS as unavailable for those few seconds.

## Fixes

- **APC Back-UPS BX** (tested on BX750MI and BX1200MI, VID:PID `051D:0002`): these models stop answering USB requests at irregular intervals, often several times an hour. The board took several minutes to restart and serve data again, and close lockups could leave it in degraded mode. It now:
  - sends far fewer requests: about 50 a minute instead of about 336, like the `pollinterval = 10` that BX owners use with NUT;
  - restarts 3 s after a lockup. Status, charge and low-battery keep updating until then, so NUT clients only miss the few seconds of the reboot. ([#60](https://github.com/maverick1982/esp32-nut/issues/60))
- **All brands:** when a USB request stays stuck, the board now restarts after 3 s instead of trying two interface restarts first, which never freed it and cost about 3 minutes. A UPS that keeps locking up but always comes back after a restart no longer ends in degraded mode or in extra waits between restarts. ([#60](https://github.com/maverick1982/esp32-nut/issues/60))
- **Model not shown in some NUT clients:** `device.mfr`, `device.model`, `device.serial` and `device.type` are now published, as NUT drivers do. Clients such as the OpenMediaVault NUT plugin read `device.model`. ([#60](https://github.com/maverick1982/esp32-nut/issues/60))

## Other changes

- **Web UI log view:** each line shows the time of the event on the ESP32, not the time the browser fetched it. After the board restarts, the view shows "Device restarted" and keeps updating instead of freezing.
- **Diagnostics:** the `[DIAG] UPS Info` log line shows the input voltage on UPS models without an output voltage, instead of `Voltage = 0.0 V`.

## Install

Flash it from the [web installer](https://maverick1982.github.io/esp32-nut/) or upload `firmware.bin` from the attached zip through OTA in the web UI. Coming from v1.5.x or earlier, use the web installer (see the [v1.6.0 notes](https://github.com/maverick1982/esp32-nut/releases/tag/v1.6.0)).
