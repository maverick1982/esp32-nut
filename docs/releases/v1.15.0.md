An ESP32-S3 can now use wired Ethernet through a W5500 module, and switch between cable and Wi-Fi by itself. The board also recovers a UPS that does not show up after a power-on, and its boot log is clearer.

## ⚠️ Upgrade notes

- **The W5500 is off by default.** Nothing changes until you turn it on in the **Network** tab.

## New features

- **Wired Ethernet with a W5500 module (ESP32-S3)** (#64). The new **Ethernet module (W5500)** section of the **Network** tab works with an external W5500 module wired to the board, or with a board that has one built in.
  - There is no common pinout, so you enter the GPIOs yourself: SCK, MOSI, MISO and CS are required, INT and RST are optional. The page refuses pins the board needs for something else, and warns about strapping pins. The README has a table of known boards.
  - Wrong pins cannot lock you out: if the W5500 does not answer, the board starts on Wi-Fi. The double reset still starts the access point.
  - **Link to use**: **Automatic** (the default) uses the cable when it has a link and gets an address, otherwise Wi-Fi. If you unplug the cable, the board switches to Wi-Fi within 30 s, and goes back to Ethernet when you plug it in again. **Ethernet** uses the cable only. **Wi-Fi** does not use the W5500.
  - The W5500 uses the Wi-Fi MAC address, so the router gives the board the same address on both links. One DHCP reservation covers both. Going back to Ethernet, the board turns Wi-Fi off first, so it is offline for a few seconds.
  - After a switch, the NUT server closes the open sessions, so Home Assistant and upsmon reconnect at once.
  - Tested on a Waveshare ESP32-S3-ETH with the PoE module and on an external module wired to an ESP32-S3 DevKit.

## Fixes

- **UPS absent after a power-on** (#78). Some UPSes are still busy when the board starts and fail to enumerate, and ESP-IDF does not retry. Until now the board retried only after one of its automatic restarts, so after a power-on the UPS could stay absent for hours. Now the board power-cycles its USB port 1 and 2 minutes after any boot if the UPS has not shown up: after a power-on, a reset, an OTA update or saved settings. In this case it does not restart, and it writes one INFO line per cycle to the System Log.
- **Clearer boot log** (#136).
  - A new board, or one with settings that were never saved, no longer prints one `nvs_open failed: NOT_FOUND` line per settings store.
  - Without a network cable, an ESP32-P4 (or a W5500 in Ethernet mode) no longer goes silent: the log repeats `No Ethernet link for N s` after 10 s, then every minute.

## Known issues

- **The web installer cannot flash an ESP32-P4 v3.1 or later yet** (#136). ESP Web Tools 10.4.0 includes esptool-js 0.6, which does not power on the flash of these chips, and the installer stops with "Failed to initialize". Flash the release zip with esptool instead (see **Release packages** in the README). Boards already running ESP32-NUT update through OTA as usual.
