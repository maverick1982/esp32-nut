The board can now find and install new releases by itself, and the NUT Server settings apply without a restart. Read **NUT commands now need credentials** below before updating if you send commands to the UPS from Home Assistant or other NUT clients without a NUT username and password.

## Before you update

- **NUT commands now need credentials.** Without a NUT username and password configured on the board, NUT clients can still read every value, but they can no longer run commands (`INSTCMD`) or change UPS variables (`SET VAR`). They get `ERR ACCESS-DENIED`, as with NUT's `upsd` when `upsd.users` has no users. Before, the board accepted commands from any client when no credentials were set. If you shut down the UPS or run battery tests from Home Assistant, set a username and password on the **NUT Server** page and the same ones in the NUT integration. Refused commands are in the System Log with the reason.

## New features

- **Online firmware updates** (#146). The board checks GitHub once a day for a newer release (the first check runs 2 minutes after the network is up) and shows a notice on the dashboard when there is one. The **OTA** page has **Check for updates** and **Download and install**: the board downloads the firmware for its own board type, checks it, writes it and restarts, in about 30 seconds.
  - The daily check is **on by default**, so boards nobody looks after still learn about fixes. It sends one request a day to `api.github.com`, which carries only the firmware version (`esp32-nut/<version>` as User-Agent), nothing about your UPS or your network. To turn it off: **Board Settings → Firmware updates → Check for updates daily**.
  - Only release builds get the notice and the install offer. Test builds (the zips we share in issues) do not.
  - Each release now also carries one `-ota.bin` per board next to its zip (`esp32-nut-v1.17.0-ota.bin` for the ESP32-S3, `esp32-nut-v1.17.0-esp32-p4-eth-ota.bin` and `esp32-nut-v1.17.0-esp32-p4-eth-v1-ota.bin` for the P4 boards). It is the same `firmware.bin` that is inside the zip. The online update uses it, and you can also upload it on the OTA page instead of the zip.
- **Uptime and Restart board** (#129, #133). The sidebar shows how long the board has been running on every page. Hover over it to see the reason of the last reset and of the last restart the firmware did itself. **Board Settings → Restart board** restarts the board after a confirmation, and the page reloads once the board is back. A restart you start this way is not shown as an automatic restart in the web UI banner, and does not count among the USB recovery restarts.
- **NUT Server settings without a restart.** Saving the **NUT Server** page applies the UPS name and the NUT credentials at once, with no board restart. When one of them changes, the board closes the open NUT sessions, so clients log in again with the new values. Saving the same values changes nothing and keeps the sessions.
- **Optional NUT credentials.** On the **NUT Server** page username and password are no longer mandatory, and you no longer type the password again on every save: leaving the field empty keeps the saved one. **Remove NUT credentials** clears them after a confirmation, and the page warns you when NUT clients can only read.

## Changes from NUT

The HID tables of the board now follow NUT as of 23 October 2026. What changes for you:

- **APC Back-UPS BX\*MI:** `shutdown.return` is now among the commands. It writes 1 to the delay-before-reboot field, as APC PowerChute and NUT do: the UPS carries it out only while on battery, turns its outlets off after a fixed grace of about 2 minutes, and back on when mains power is present, even if it came back during the grace. It is the only shutdown these units actually carry out. The `shutdown.reboot` command, which writes 10 to the same field, is accepted by the UPS but ignored.
- **Legrand Keor:** `ups.beeper.status` now shows `disabled`, `enabled` or `muted`, as NUT reads it, and `beeper.mute` is now among the commands. `beeper.disable` now writes 1 instead of 3 (in NUT, 3 means muted). `beeper.toggle` stays.
- **Eaton 5P Gen2** (650/850/1150/1550 i G2 and iR G2): recognized as the Eaton 5P series, so `battery.voltage` is published as on the other 5P models.

## Fixes

- **The web installer flashes the ESP32-P4 v3.1 and later** (#136). Before, it stopped with "Failed to initialize" on these chips, because its flashing library did not power on their flash memory. The installer now uses ESP Web Tools 10.5.2, which does.
- **UPS name in the sidebar for units that report no model.** The sidebar showed "UPS: Unknown Model" for UPS units without a model name, such as Q* (Megatec) units that do not answer the `I` command. It now shows the manufacturer when there is one (for example "UPS: Ippon"), and "Unknown Model" only when the UPS reports neither.

## Install

Flash it from the [web installer](https://maverick1982.github.io/esp32-nut/), upload `firmware.bin`, the `-ota.bin` of your board or the whole zip through OTA in the web UI, or, from the next release on, use **Download and install** on the OTA page.
